# SC で fetch / CC で更新するハイブリッド構成メモ

## 結論

- CC の Server Function から `updateTag` + `refresh` を呼べば、同一 route の SC をまとめて再実行できる。
- ただし `useTransition` の `isPending` は **RSC のストリーミングとコミットが完了するまで** 解除されない。SC が多い・重いページでは、ボタンの「更新中...」がその分だけ長く残る。
- `use cache` でキャッシュが効いている SC は即座に返るので、`isPending` の長さには影響しない。

---

## 1. 検討している構成

データ取得は Server Component、更新操作は Client Component に寄せる。SC と SPA のハイブリッド。

想定しているユースケース:

- blog ページ本体は SC
- コメント一覧だけ CC
- コメントのいいねボタンなど、細かい更新もこの構成に乗せる

### 懸念（未検証）

- グローバルな状態共有が面倒になりそう。
- 状態を CC 側に持たせると、`updateTag` などの Next のキャッシュパージ機構が使えず、SC 側のキャッシュと CC 側の state で二重管理になる。

---

## 2. 実装

### Server Function（同一 route のキャッシュを更新する）

```ts
"use server";

import { refresh, updateTag } from "next/cache";
import { BLOGS_CACHE_TAG } from "../../blogs/_data/cache-tags";

export const updateBlogTag = async () => {
  updateTag(BLOGS_CACHE_TAG);
  refresh();
};
```

`updateTag` でタグ付きキャッシュをパージし、`refresh` で現在のページを再取得させる。

### 呼び出し側の Client Component

```tsx
const [isPending, startTransition] = useTransition();

return (
  <form
    onSubmit={async (e) => {
      e.preventDefault();
      startTransition(async () => {
        await updateBlogTag();
      });
    }}
  >
    <Button type="submit" disabled={isPending}>
      {isPending ? "更新中..." : "ブログを最新に更新"}
    </Button>
  </form>
);
```

---

## 3. 実行時の挙動

submit してから `isPending` が解除されるまでの流れ。`isPending = true` の区間がどこまで続くかが要点。

1. submit
2. **`isPending = true`** ← ここから
   1. Server Function 発火
   2. キャッシュパージ（`updateTag`）
   3. `refresh`
   4. レスポンス / Server Function 終了
   5. 現在のページの **すべての SC が再実行**
   6. RSC ストリーミング開始 → 完了
   7. コミット
3. **`isPending` 解除** ← ここまで

つまり `isPending` は Server Function の完了ではなく、**コミット完了**までを表す。ストリーミングに時間がかかればそのまま UI のペンディング時間になる。

### 例外

`use cache` でキャッシュが残っている SC は即座に返却されるため、再実行されても `isPending` の長さには影響しない。
